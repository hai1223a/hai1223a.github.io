## Deepseek-V3

[[论文地址] DeepSeek-V3 Technical Report](https://arxiv.org/abs/2412.19437)

DeepSeek-V3 在 V2 的架构基础上扩大模型规模，改进 MoE 负载均衡，并系统优化训练效率和模型能力。

### 无辅助损失负载均衡

> 为什么MoE需要负载均衡？
>
> 在实际训练时，Router可能更加偏爱某几个专家，导致其接收大量token，带来两个问题：一是部分专家训练不充分，二是在多 GPU 训练时，某些设备负载过高，拖慢整体训练速度。

V2 的思路是：既然 Router 本身不会主动追求负载均衡，那就在训练目标中增加一个负载均衡的约束，让它同时考虑模型效果和计算效率。

V2 设计了三种辅助损失：

- **专家级均衡损失**：避免 Token 过度集中到少数专家。
- **设备级均衡损失**：尽量让不同 GPU 承担均衡的计算负载。
- **通信均衡损失**：避免某些 GPU 接收过多 Token，成为跨设备通信的瓶颈

于是，总训练目标可以概括为：

```text
总损失 = 语言模型损失 + 专家均衡损失 + 设备均衡损失 + 通信均衡损失
```

这些辅助损失会通过梯度参与训练，间接调整 Router 的参数，使专家分配趋向均衡。

#### V2 负载均衡方案的问题

> 模型的预测目标和负载均衡目标并不总是一致。

某个专家特别擅长处理代码 Token，Router 本来希望多将代码 Token 分配给它；但负载均衡损失发现该专家已经接收了太多 Token，就会推动 Router 减少对它的选择。

这两个目标发生了冲突：

- 辅助损失权重太大，可能干扰模型学习最合适的专家分工。
- 辅助损失权重太小，又可能无法有效缓解负载不均。

此外，V2 的辅助损失只能鼓励负载均衡，无法严格保证每个设备的计算量始终相同。因此，V2 还采用了训练阶段的 Token 丢弃策略：设备超出计算容量时，优先丢弃匹配分数较低的 Token。

#### V3的负载均衡方案

V3 的改进思路是：既然辅助损失会与模型原本的学习目标产生冲突，那么久不再主要依靠辅助损失，而是直接调整 Router 的选择过程。也就是**无辅助损失负载均衡策略（Auxiliary-Loss-Free Load Balancing）**。

> 具体流程如下：
>
> **第一步：正常计算专家匹配分数。**
>
> Router 根据输入 Token 计算它与各个专家的匹配分数，分数越高，通常越适合处理该 Token。
>
> **第二步：根据动态偏置选择专家。**
>
> 为每个专家增加一个偏置项。选择 Top-K 专家时，使用“原始匹配分数 + 偏置”进行排序。
>
> 偏置越大，专家越容易进入 Top-K；偏置越小，专家越不容易被选中。
>
> **第三步：根据真实负载更新偏置。**
>
> 每个训练 Step 结束后，统计各专家的负载：
>
> - 某个专家过载，就减小它的偏置。
> - 某个专家负载不足，就增大它的偏置。
>
> 不断重复这个过程，就可以动态调节后续 Token 的分配。
>
> **第四步：专家输出仍然使用原始匹配分数。**
>
> 这是整个设计最关键的一点：偏置只影响专家是否入选，并不直接影响专家输出的加权值。实际的 gating weight 仍然根据原始匹配分数计算。
>
> 因此，模型可以通过偏置调整负载，而不必主要依赖一个额外的负载均衡损失来改变 Router 的优化目标。

这种方案将“好的预测效果”和“负载均衡”两个目标拆开，通过偏重更新机制来处理负载均衡问题，能够减少负载均衡目标与语言模型学习目标之间冲突。**需要注意，V3 并不是完全取消了所有辅助损失。论文仍然保留了一个权重极小的序列级辅助均衡损失，用来防止单条序列内出现极端的负载不均。**

### MTP

DeepSeek-V3 引入了 MTP（Multi-Token Prediction，多 Token 预测）机制：除了预测下一个 Token，还增加一个额外预测模块，负责预测再往后的一个 Token。

* 在训练中引入该模块，能够促使隐藏表示包含更多有利于预测未来 Token 的信息，增强模型能力。
* 在推理中可以配合Speculative Decoding（投机解码）使用，提高推理的速度。

其结构如图所示，包含RMSNorm归一化，一个线性层，一个transformer Block，以及与主模型共享的Embedding Layer，Output Head。

<img src="{{ "/images/49.png" | relative_url }}" alt="MTP 模块结构与多 Token 预测流程" style="max-width: 100%;" />
<p class="image-caption">图 2：MTP 模块结构与多 Token 预测流程</p>

> MTP的工作流程: 主模型负责预测 `tᵢ₊₁`，MTP 模块则在结合主模型的隐藏表示与 tᵢ₊₁ 的 Embedding 后，进一步预测 `tᵢ₊₂`。并且通过多个MTP进行连接，还可以同时预测`tᵢ₊3`，`tᵢ₊4`...等。

在训练中，将总的训练目标理解为

$$
\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{main}} + \mathcal{L}_{\text{MTP}}
$$

其中

$$
\mathcal{L}_{\text{MTP}} = \frac{\lambda}{D} \sum_{k=1}^{D} \mathcal{L}_{\text{MTP}}^{k}
$$

D表示额外预测深度，λ 控制 MTP 辅助训练目标的影响程度。在V3中配置D=1，即V3只有一个MTP，预测未来2个token。
