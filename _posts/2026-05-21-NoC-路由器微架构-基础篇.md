以一个2D mesh网络的经典路由器为例进行介绍。其包括五个方向输入输出，`东`，`南`，`西`，`北`和`本地`。主要部件包括输入缓冲（input buffers）、路由计算逻辑（route computation logic）、虚通道分配器（virtual channel allocator）、开关分配器（switch allocator）以及交叉开关（crossbar switch）。

## 缓冲与虚通道

### 缓冲组织结构

几乎所有的路由器都设计了输入缓冲，因为其允许使用单端口存储器实现。而常见有三种buffer的组织形式：

1. **单个固定长度队列**：如下图图a所示，没有使用虚通道，存在严重的队头阻塞（head-of-line blocking）问题。
2. **多个固定长度队列**：如下图图b所示，我们称其中的每个队列为虚通道。
3. **多个可变长度队列**：如下图图c所示，为了缓解固定长度队列的负载不均衡问题，该方法让所有虚通道共享一片buffer，通过队头队尾追踪，并保证每个虚通道至少持有一个flit buffer空间以避免死锁。代价是更加复杂的电路来最终队头队尾。

<img src="/images/34.jpg" alt="Input buffer organizations with virtual channels" style="zoom: 50%;" />
<p class="image-caption">图 2：输入缓冲与虚通道的常见组织方式</p>

### 虚通道和buffer的最小数量

虚通道的主要功能是避免死锁和提升性能。前者可能依赖一定数量的VCs对不同类型的packet进行**分类**，例如多核中的request和response就得区分；在一类VCs中，也可能需要**逃逸VC**来保证无死锁。后者需要一定数量VCs来消除**队头阻塞问题**。同时考虑不同流量模式，在buffer数量固定的前提下，少而深的VCs安排和多而浅的VCs安排会得到不同的效果。

对于buffer大小，为了维持功能正确性，每个虚通道至少要一个flit buffer。而为了维持满吞吐，也需要足够数量的buffer覆盖**缓冲周转时间**。

### 输入VC的状态信息

* **全局状态（Global, G）：** 空闲/ 路由中 等待输出虚通道/ 等待输出虚通道中的信用/ 活跃。活跃虚通道可以执行开关分配。
* **路由（Route, R）：** 该字段用于开关分配。输出端口由head flit在路由计算之后填入，而同一个packet中的所有flit将会继承这个字段。
* **输出虚通道（Output VC, O）：** 该packet的输出虚通道，即下游路由器处的虚通道。该字段由head flit在虚通道分配之后填入，并由该packet后续的所有flit使用。
* **信用计数（Credit Count, C）：** 输出端口 R 上输出虚通道 O 中的信用数量，即下游路由器中的flit buffer数量。该字段由body flits和tail flits使用。
* **指针（Pointers, P）：** 指向头flit和尾flit的指针。如果缓冲被实现为多个可变长度队列共享的池，如上所述，则需要该字段。

## 仲裁器与分配器

仲裁器表示了$N \to 1$的选择，分配器表示$N \to M$的选择。在路由器中，交叉开关端口和输入虚通道是需要被仲裁的资源，因此有了VA和SA。对于有虚通道的路由器，需要使用VA完成输出虚通道（也就是下游的输入虚通道）对输入虚通道的授权，一个packet中只有head flit是需要经过VA的。然后，需要SA为不同的输入虚通道分配交叉开关端口，让他们有机会占据物理link，这个是每个周期都需要进行的。

### 轮转仲裁器

例如存在A，B，C，D四个请求通道，最初优先级是`A>B>C>D`，第一轮仲裁命中A，那下一轮优先级会变为`B>C>D>A`;第一轮仲裁命中C，那么下一轮优先级会变为`D>A>B>C`.

<p class="image-caption">图 6：轮转仲裁器示例</p>

### 矩阵仲裁器

这是一个最少使用者仲裁器，其利用一个优先级矩阵，记录任意两个请求者之间的优先级。例如存在A，B，C，D四个请求通道，会维护一个优先级矩阵，其中wAB = 1表示A的优先级比B高，而wAB = ~wBA。所以只需要维护整个矩阵的上三角区域。

```
      A  B  C  D
A     -  wAB wAC wAD
B    wBA  -  wBC wBD
C    wCA wCB  -  wCD
D    wDA wDB wDC  -
```

最终选中的请求者必须满足：（1）它当前存在请求；（2）他的优先级比其他所有请求者高。以B为例，从矩阵看就是，B所在行均为1，B所在列均为0。

下个周期需要降低选中者的优先级，操作是将B所在行变为0，B所在列变为1。

### 可分离分配器

将N-M的分配器拆分为两级仲裁器。以SA为例介绍：

假设：（1）4 个 input port；（2）每个 input port 有 3 个 VC；（3）4 个 output port

第一级仲裁器包括4个3选1仲裁器，分别从4个input port中选出1个候选VC。

第二级仲裁器包括4个4选1仲裁器，每个output port会从4个候选VC中选出1个命中VC。

表现为请求矩阵如下，矩阵中的行表示一个input port的VC对output port的选择，所以第一阶段就是每一行中选一个1。第二阶段，再由output port在每一列选一个1。

```
          Output0  Output1  Output2  Output3
Input0      0        1        1        0
Input1      0        0        1        0
Input2      1        0        1        0
Input3      0        0        0        1
```

但这种方法十分低效，由于第一阶段仲裁不知道第二阶段仲裁的信息，造成第一阶段仲裁出如下结果：

```
          Output0  Output1  Output2  Output3
Input0      0        0        1        0
Input1      0        0        1        0
Input2      0        0        1        0
Input3      0        0        0        1
```

这样就极大地降低了端口的利用率。但是可分离分配器很适合流水，追求极高频率、低面积、低功耗的路由器。

### 波前分配器

该分配器使用整体信息进行分配，同样假设请求矩阵，分配需要遵守（1）每个output最多只能分给一个input；（2）每个input最多只能安排一个output。因此每一行安排一个行token，每一列安排一个列token。一个格子只有同时具备行token和列token并且自身存在请求才能被选中。

```
          Output0  Output1  Output2  Output3
Input0      1        0        0        0
Input1      0        1        0        0
Input2      0        1        0        0
Input3      0        0        1        0
```

而行token和列token需要进行传播，他们会从一条对角线开始进行。比如一开始是主对角线，`[0,0][1,1][2,2][3,3]`会同时获得行token和列token。其中`[0,0][1,1]`命中，他们对应行列的token就不会移动了，而in2，in3两行的行token会向右循环移动；out2，out3两列的列token会向下循环移动。在组合逻辑中总会匹配到`[3,2]`。

波前分配器适合用于需要较好匹配质量的地方，但是（1）需要维持二维阵列结构，实现更复杂；（2）token 传播路径可能较长；（3）为了公平性应该每轮都切换起始优先级，即改变最初的对角线。

### 路由函数，SA与VA的组织关系

核心问题是：当路由选择更灵活、或者 router 采用投机执行时，allocator 的设计会明显变复杂。

#### 1. 自适应路由会增加 SA 和 VA 的配合复杂度

对于 **确定性路由（deterministic routing）**，每个 flit 只有一个确定的输出端口，因此**SA** 只需要为这个输出端口发起请求。

而对于 **自适应路由（adaptive routing）**，路由函数可能返回多个候选输出端口。此时有两种解决方法

*  SA 可以同时对多个候选输出端口发请求，但最终被 **SA** 授予的输出端口必须和 **VA** 授予的输出 VC 保持一致。
* 路由函数每次只返回一个候选输出端口。如果该 flit 没有成功获得对应的 output VC，则重新执行路由，尝试另一个候选输出端口。

#### 2. VA 的复杂度取决于路由函数返回的信息粒度

如果路由函数直接返回一个具体的输出 VC，例如`(East；VC2)`。那么 VA 只需要在竞争同一个 output VC 的 input VC 之间做仲裁，设计相对简单。

如果路由函数只确定物理输出方向，但返回多个候选 VC，例如`（East；VC0, VC1, VC2, VC3）`。那么 VA 不仅要决定哪个 input VC 成功，还要决定它获得哪个 output VC。此时 VA 就变成一个多请求、多资源的 allocator 问题，通常可以用 **可分离分配器**这类结构实现。

最复杂的情况是：路由函数同时返回多个候选 physical channel，并且每个 physical channel 上又有多个候选 VC。例如`（East；VC0, VC1, VC2, VC3。North，VC0, VC1, VC2, VC3）`。这种情况下，VA 需要在所有候选 physical channel 和 candidate VC 之间做匹配，因此功能最复杂。

#### 3. 投机式 VC router 中，SA 可以和 VA 并行执行

普通 VC router 中，head flit 通常需要先完成 VA，拿到下游 output VC，然后再执行 SA，申请通过 crossbar。

投机式虚通道路由器（speculative virtual channel router）为了降低延迟，会让 head flit 在 VA 尚未完成时，提前投机性地申请 SA。如果 VA 和 SA 同时成功，head flit 就可以直接进入 switch traversal，从而减少一个 pipeline stage 的等待。但这种方式存在风险：如果 SA 成功而 VA 失败，那么 flit 实际上不能前进，已经预留的 crossbar 通路就会被浪费。

#### 4. 非投机请求必须优先于投机请求

在 speculative router 中，请求分为两类：

```text
non-speculative switch request  非投机开关请求
speculative switch request      投机开关请求
```

非投机请求表示该 flit 已经确定具备前进条件，例如 body flit 和 tail flit 已经继承了 head flit 分配好的 VC，因此它们申请 crossbar 是确定有效的。投机请求通常来自 head flit。head flit 还没有确定能否拿到 output VC，但提前申请 crossbar。

因此设计上必须保证：

```text
non-speculative request > speculative request
```

一种实现方式是使用两个并行的 switch allocator：

```text
SA_non_speculative：处理非投机请求
SA_speculative：处理投机请求
```

最终选择结果时，非投机请求优先。如果没有非投机请求竞争某个输出端口，则投机请求可以成功获得该端口。

## 路由器流水线

### 标准流水线

| 阶段              | 缩写 | 功能                                                         |
| ----------------- | ---- | ------------------------------------------------------------ |
| Buffer Write      | BW   | 根据输入 VC 将头流片（head flit）或体流片（body flit）写入缓冲 |
| Route Computation | RC   | 对头流片进行路由计算，决定输出端口                           |
| VC Allocation     | VA   | 为头流片分配下游路由器的虚通道（VC）                         |
| Switch Allocation | SA   | 申请 crossbar 的输入输出端口                                 |
| Switch Traversal  | ST   | 流片从缓冲读出，通过 crossbar                                |
| Link Traversal    | LT   | 流片沿链路到达下一个 router                                  |

标准流水线包括六个阶段，其中head flit经过全部六个阶段，body flit不经过RC和VA阶段。

### 举例解析

一个mesh的router，拥有east，west，south，north，local五个输入输出端口。每个端口有一个由多个VC队列组成的buffer，我们称一个VC队列为一个input VC。

#### BW

当有flit进入输入端口后，首先需要将其写入对应input VC中，通常是插入这个VC队列的尾部，这一步称为BW，这里五个输入端口的BW操作是并行。

#### RC

每一个input port都有一个RC部件，一个RC部件会对一个input port的所有input VC的队头flit都进行RC操作。只有head flit会进行RC。

#### VA

每一个input port都有一个VA部件，由于路由算法不同，最复杂时，一个input VC可能对应了多个output port的多个下游VC。因此VA进行分配时，是对一个input port中所有使用了相同output port的同一个下游VC的多个input VC进行仲裁，最终形成多个(input VC - 下游VC)虚通道对。例如（input VC1 - east 下游 VC2），（input VC3 - east 下游 VC4），（input VC7 - west 下游 VC1）。只有head flit会进行VA。

#### SA

将五个VA的结果汇总过来，进行分配。每个周期每个output port只能输出一个flit，因此SA会为每个output port选择一个(input VC - 下游VC)虚通道对，也可能让某个output port轮空。

#### ST

成功通过 SA 的流片从 buffer 读出，通过 crossbar 传到输出端口。ST 逻辑上只是物理搬运 flit。

#### LT

ST 阶段结束后，flit 沿链路发送到下一个 router 的输入端口。LT 只负责链路传输，不涉及分配或仲裁。

### 低负载旁路（Low-load Bypass）

在网络流量不大时，没有竞争的flit通过旁路跳过BW和SA阶段，直接进入ST阶段，如下图所示

![Low-load bypass pipeline](/images/41.jpg)
<p class="image-caption">图 8：低负载旁路结构</p>

低负载时，**输入缓冲里通常没有排队的 flit**，也就是没有竞争。

- **BW 阶段（Buffer Write）**是为了把 flit 写入缓冲以等待竞争，**没有竞争就不需要写入缓冲**。
- **SA 阶段（Switch Allocation）**是为了在 crossbar 资源冲突时仲裁，**没有竞争自然也不需要仲裁**。
- **VA 阶段（Virtual Channel Allocation）**仍然需要，因为即使没有竞争，也要确保 flit 占用一个下游 VC，以保证后续正确前进。

所以旁路可以跳过 **BW + SA**，直接进入 **ST**，前提是 VA 已经完成或可以与 setup 并行。

而为了判断是否存在竞争，需要在ST前增加setup来尝试配置crossbar，如果成功就进入ST，如果失败就重新写回缓冲区BW。这个也可以和前瞻路由结合，即RC/VA/setup同时执行

### 投机虚通道分配（Speculative VA）

在标准流水线中，需要先进行VA得到下游有效的虚通道，然后通过SA在该输出端口和虚通道上进行仲裁。而该方法将SA和VA并行执行，在SA仲裁时使用推测的虚通道。

- 如果 speculative 成功，head flit直接进入 **ST（Switch Traversal）**。

- 如果 speculative 失败，flit回退到 BW 或其余 pipeline 阶段重新执行。

当然后续body flit和tail filt会继承head flit的VC，是非推测请求，将保证正确性。

### 虚通道选择 (VC Selection) 

VC Selection（虚通道选择）是 **一种简化 VA 的方法**，去掉完整 VA 阶段，每个输出端口维护一个队列free vc queue，记录该端口下游所有空闲 VC id。每个输出端口的SA获胜者被分配free vc queue的队头虚通道标识。仅当输出端口的free vc queue非空时，head flit才会进入SA阶段。body flit和tail flit直接进入SA。
